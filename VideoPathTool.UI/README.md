# 录制工具图形界面（WPF）

把原来只能靠控制台菜单驱动的录制流程做成窗口，并加了一个可暂停、可中途改参数的执行调度器。

## 启动

```
F:\GENSHIN1\VideoPathTool.UI\bin\Debug\net8.0-windows\VideoPathTool.UI.exe
```

或从源码：

```
cd F:\GENSHIN1\VideoPathTool.UI
dotnet run
```

首次启动会把控制台工具已有的 `VideoPathTool.config.json` 复制到自己目录，所以视频路径、
地图资源、输出路径都直接可用；之后窗口维护自己的一份，改参数不会影响控制台工具。
`glider.onnx` 会在构建时一并复制到输出目录。

## 界面

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ▶开始 ⏸暂停 ▶继续 ⏹停止 │ ●空闲    重扫滑翔 载入CSV │ 重新导出 导出到… │ ☰参数
│ 视频链接 [__________________________] 下载并识别 分P列表 打开下载目录    │
├──────────────────────────────────────────────────────────────────────────┤
│  进度条                                                                   │
│  阶段 / 视频时间 / 匹配率 / 已录点 / 已用/剩余                             │
├──────────────────────────────────────────────────────────────────────────┤
│  概览 │ 地图 │ 视频与标定 │ 滑翔窗口 │ 点位操作 │ 合集分P │ 日志 │ 参数    │
└──────────────────────────────────────────────────────────────────────────┘
```

参数面板原本是左侧常驻栏，占了将近三分之一宽度但改得很少，现在收进「参数」标签页，
内容区拿满宽度。`Ctrl+B` 或工具栏「☰ 参数」在它和上一个标签页之间来回跳。

界面按**实际做事顺序**分成四块，而不是按控件类型堆在一起：

| 区域 | 管什么 | 什么时候用 |
|---|---|---|
| 工具栏第一行左 | 开始 / 暂停 / 继续 / 停止 | 录制时 |
| 工具栏第一行右 | 重扫滑翔、载入 CSV ‖ 重新导出、导出到… | 收尾时 |
| 工具栏第二行 | 链接 → 下载并识别 / 分P列表 / 打开下载目录 | 换视频时 |
| 左侧参数栏 | 全部可调参数（5 组，可折叠） | 需要调的时候 |

标签页顺序对应流程：**概览**（结果 + 点位编辑）→ **地图**（路线的空间视图）→
**视频与标定**（看画面、标滑翔）→ **滑翔窗口** → **点位操作**（修整）→
**合集分P**（批量入口）→ **日志** → **参数**。

### 概览：直接改导出的点位

录制完的路径点全列在「路径点」表格里，X/Y 可以直接改、行可以直接删，
改完点「重新导出」就写进 JSON——不用重跑视频。

- 表格一旦被改过，导出就以表格为准（日志会写一行说明），
  否则 `重新导出` 会用滑翔窗口重新算一遍、把手工修改悄悄覆盖掉
- 「重建路径点」用来放弃手工修改，按当前滑翔窗口 / 点位操作重新生成
- 双击一行跳到该点对应的画面，方便核对
- 悬停提示会显示「已手工修改」还是「未改动」

### 播放：跟着真实时间走

播放不是"一次定时器读一帧"，而是**以墙上时钟为准**：每帧算出视频此刻应该在哪
（起点 + 真实流逝 × 倍速），解码落后就丢帧追上，超前就等一等。这样：

- 拖动进度条后按播放，**从当前位置继续**，不会跳回开头
- 声音（独立的 `MediaPlayer`）每 0.2 秒对一次表，偏差超过 0.25 秒才拉回，
  既不累积漂移，也不会频繁 seek 出爆音
- 慢速编码（AV1）卡一下不会让画面和声音越走越远

「是否已经播到结尾」用解码器报的真实时长判断——以前用进度条的最大值，
那个值在视频载入前是 1，于是任何位置都被判成结尾，一点播放就回到 0。

### 监控小窗：边录制边看攻略

录制时右下角会浮出一个置顶小窗（也可以点工具栏「监控小窗」手动开）：

- 显示**正在录制的那一帧**对应的画面，标题栏写着视频时间与匹配率
- 拖标题栏移动，✕ 关闭；窗口可缩放
- 它用自己的解码器，不和录制、也不和主界面的预览抢

「参数」里的 `auto_open_mini_preview` 可以关掉自动弹出。
### 地图：把路线画在地图上

**地图**页把整条路线画在提瓦特地图上，滚轮缩放、拖动平移：

- 绿色是移动段，橙色是传送段（`type = teleport`）
- 单击标记 → 选中概览里对应的行；双击地图 → 把选中点位挪到该处
- 「适应路线」把视野收回到整条路线
- 底图默认用 BetterGI 附带的 `Teyvat_0_256.png`，那是给特征匹配用的**灰度图**，
  所以在「参数」里可以指定任意同尺寸（5632×4864）的彩色地图替换

坐标换算与 BetterGI 的地图层一致：图像原点在 (4096, 3072)，
游戏坐标 **+X 向左、+Y 向上**，1 像素 = 4 游戏单位。这条公式是从
`SceneBaseMap.ConvertGenshinMapCoordinatesToImageCoordinates`
（`scale = 2048 / 1024 = 2`，256 图层再除以 8）核对出来的，不是猜的。

**关于清晰度**：仓库里能拿到的提瓦特底图只有 BGI 那一张 5632×4864 的灰度匹配图——
整个大陆 5632 像素，1 像素约 4 游戏单位，一条几百单位的路线本来就只有几十像素。
所以自动适应最多放大到 4 倍（再放只是把底图糊成一片，看起来像"误差"），
放大超过 2.5 倍时改用像素级缩放，宁可看到方块也不给一团模糊。
想要更清晰的底图，在「参数 → 地图图片」里指定同尺寸的彩色地图即可；
路线本身的位置精度不受底图影响。

```
px = 4096 - x / 4
py = 3072 - y / 4
```

- **概览**：采样/匹配统计、路径点与 fly 点数量、断点列表（传送 / 跟踪丢失）。
  匹配率低于 60% 时会弹出一条黄色提示，因为那几乎总是小地图圆心设错了。
- **视频与标定**：内嵌播放器 + 标注时间轴（见下文）。
- **滑翔窗口**：把检测到的滑翔段列成表格，可勾选/取消、改起止时间、增删行。
- **点位操作**：在某个视频时刻挂动作 / 点位类型 / 坐标微调。
- **合集分P**：一个合集的多个分P 排队处理（见下文）。
- **日志**：与后台线程的完整日志，带时间戳。

左侧参数栏里，`输出文件` 一行同时代表 JSON、`debug.csv` 和 `project.json`——三者永远在
同一个目录，各占一行只会把真正要改的参数挤下去。

### 进度里的四个数字

`[进度] ... 采样 901（成功 804 失败 0 无效 97）` —— 括号里三项加起来等于采样数。

| 计数 | 含义 |
|---|---|
| 采样 | 按采样率取了多少帧 |
| 成功 | 小地图匹配上了 |
| 失败 | 匹配跑了但没对上（真·失败） |
| 无效 | **根本没有可用小地图**：开着地图界面、加载中、过场动画 |

「无效」不算失败，因为那几帧本来就没有小地图可匹配；它们既不会产生坐标，也不会拉低匹配率。
如果「无效」占比很高（比如超过 30%），通常说明小地图圆心/半径圈错了，
匹配器拿到的是别处的画面，自然一直被判定为无效。

从调试 CSV 恢复时，统计只能按"已接受的点"重建，所以那时会看到采样=成功、失败=无效=0、
匹配率 100%——这只说明 CSV 里只剩接受的点，不代表录制时没有无效帧。

### 左侧参数栏可以收起

左侧参数栏占 392px，看画面时嫌窄就直接收起来，视频区会占满整个宽度。

| 方式 | 操作 |
|---|---|
| 折叠把手 | 面板右边缘那条细条，上半截的 `«` 点一下收起 / `»` 展开 |
| 拖动 | 细条下半截是分隔条，可直接拖宽度（300px 起） |
| 工具栏 | 顶部「☰ 参数」按钮 |
| 快捷键 | **Ctrl+B**（在输入框里打字时也能用） |

收起状态和拖动后的宽度都会记进配置，下次打开保持原样。
收起时工具栏那个按钮会变成蓝色，提示面板当前是隐藏的。

参数栏里的分组（视频与输出 / 小地图 / 采样与匹配 / 路径简化 / 滑翔检测）可以单独展开收起。

## 执行调度器

四个按钮对应一个明确的状态机：

| 状态 | 可用的操作 |
|---|---|
| 空闲 | 开始 |
| 运行中 | 暂停、停止 |
| 已暂停 | 继续、停止 |
| 停止中 | — |
| 已完成 / 已停止 / 失败 | 开始、重扫滑翔、重新导出 |

### 暂停语义：不丢数据

暂停是**协作式**的：录制循环每帧之间检查一次暂停闸门，所以恢复后从"上一帧处理完"的
精确位置继续，不会重新开始，也不会丢掉已经录到的点。阶段切换处同样可以暂停
（例如刚录完、正要开始扫滑翔时）。

停止会取消令牌，并**保留已经采集到的数据**——取消的运行仍然能导出一份部分路线。

### 可以暂停后热改的参数

每帧都会重新读取这些值，所以"暂停 → 改 → 继续"立即生效：

- 小地图圆心 X/Y、半径（这是最实用的：发现圆偏了，暂停改完继续，不用从头再来）
- 采样 FPS
- 置信度阈值、SIFT 内点门槛、重同步参数
- 滑翔检测开关与 YOLO 阈值（对后续的滑翔扫描生效）

需要重新「开始」才生效的：视频路径、起止秒、输出路径、地图资源目录。
界面上这些项改动后只保存配置，不会试图中途切换（切换视频会让已录的点失去意义）。

## 三种微调方式

**1. 中途改参数**
暂停 → 改小地图/阈值 → 继续。适合"跑到一半发现圆偏了一点"。

**2. 改滑翔窗口后重新导出（最快）**
跑完一次后，到「滑翔窗口」页取消勾选误报的段、或手工添加漏掉的段，
点「重新导出」。**完全不读视频**，毫秒级完成，因为位置点已经缓存在内存里。

```
导出前：4 个路径点，3 个 fly
取消勾选 17.67–24.33 段 → 重新导出
导出后：4 个路径点，1 个 fly
```

**3. 从调试 CSV 重建**
点「载入 CSV」选一份 `*_debug.csv`，位置点从文件恢复，完全不碰视频。
适合"位置没问题，只想调简化参数或滑翔段"。
注意 CSV 里没有滑翔信息，载入后需要「重扫滑翔」或手工添加。

改动任何一个参数都会自动存盘（防抖 0.7 秒），关闭窗口时再存一次。

## 给链接就能下载识别

工具栏第二行是链接输入框：粘贴 B 站等站点链接 → 点「下载并识别」，会依次完成

1. 用 yt-dlp 下载**视频流与音频**（`avc1 + mp4a`，要 AVC 是为了解码快）到固定下载目录
2. 把视频路径切到新文件，并按视频名重新推导 JSON / CSV 路径
3. 如果是 AV1/HEVC，先转一份 H.264 预览副本（见下），H.264 直接跳过
4. 自动检测小地图圆（新视频参数未知，先探一遍）
5. 直接开始录制

日志会逐条记下每一步。下载进度走顶部进度条，阶段显示「解析标题 / 已识别 / 下载中 / 已存在 / 合并中 / 完成」。

### 合集链接：先列分P，再让你选

B 站合集链接经常是 `https://www.bilibili.com/video/BVxxxx/` 这种形式，不带 `?p=`。
直接按单视频处理只会拿到 P1，所以这类链接会先让你在「**合集分P**」页里挑。

- 点「下载并识别」遇到合集链接，会自动跳到该页并列出全部分P（标题 + 时长）
- 勾选一个或多个，点「依次处理选中」：按 P 号顺序做「下载 → 录制 → 导出」，每条生成自己的路线目录
- 中途按「停止」或「停止批量」：当前这条结束后不再继续
- 链接本身已带 `?p=N` 时不再询问，直接用；单视频不跳页，照常一键下载

分P 列表走的是 bilibili 的 `pagelist` 接口，**一次请求拿全部**（实测 40 个分P 耗时 0.4 秒）。
不用 yt-dlp 是因为它要逐个完整解析，约 1.5 秒一个，40 个分P 光是列出来就要一分钟。

接口不可用（网络/改版）时会自动退回"按单条处理"，不影响正常下载。

某一条匹配到 0 个点时会在日志里明确告警——通常是这一段没有小地图（纯菜单/文字卡），
或者左侧「小地图」的圆心半径不适用于这个视频。

### 文件命名：用真实标题，合集带 P 序号

下载前先向站点查一次元数据（`yt-dlp -J`），拿标题来命名，而不是用 URL：

| 链接 | 文件名 |
|---|---|
| `.../video/BV1GJ411x7h7` | `【官方 MV】Never Gonna Give You Up - Rick Astley.mp4` |
| `.../video/BV1GJ411x7h7?p=1` | `【官方 MV】Never Gonna Give You Up - Rick Astley_P1.mp4` |

P 序号的来源按优先级取：

1. `playlist_index`（下载合集播放列表时 yt-dlp 直接给）
2. 视频 id 的 `_pN` 后缀（bilibili 分P 就是这样暴露的，`playlist_index` 反而是空的）
3. URL 里的 `?p=N`

标题里 Windows 不允许的字符（`\ / : * ? " < > |` 和控制字符）会换成 `_`，
中文原样保留；长度截到 80 字符；`CON`、`NUL` 这类保留名加前缀避开。

命名解析失败时（比如站点临时查不到）会退回到 yt-dlp 自己的模板
`%(title).80s%(playlist_index&_P{}|)s`，效果一样，只是没法提前显示。

**依赖**：`F:\GENSHIN1\tools\yt-dlp.exe`（首次使用前放好，或把它的目录加入 PATH）。
只有下载到需要转码的格式时才需要 ffmpeg。

### 下载优先选 H.264，避开 AV1

`-f "bv*[vcodec^=avc1]/bv*[vcodec^=avc]/bv*/b"`——先要 AVC，没有再退回其它。

这不是口味问题，是实测出来的：B 站现在会给新客户端推 AV1，而 AV1 软解极慢。
同一个 1080p 视频实测：

| 编码 | 单帧解码 | 单次 seek（GOP 5 秒） |
|---|---|---|
| H.264 | ~10 ms | ~0.2 s |
| AV1 | ~85 ms | **1.4–3.3 s** |

AV1 下录制整条视频要多花好几倍时间，编辑器里拖进度条也要等一两秒才出画面。
画质差异对地图匹配毫无意义，所以直接要 AVC。

已经下成 AV1 的视频不会自动变快——删掉重下即可（这次会拿到 H.264）。

下载会**连音频一起要**（`+ba`），因为预览时能听到声音对确认路线很有用。

### 预览副本：把慢视频转成能拖的

代码本身没法让 AV1 快起来，但可以换个文件：

点右侧「**生成快速预览**」，用 ffmpeg 把它转成 H.264 副本 `<原文件名>.proxy.mp4`，
之后编辑器自动读副本（视频信息行会显示 `[预览副本]`）。

**下载后会自动做这件事**：先探测编码，只有 AV1 / HEVC 才转；本来就是 H.264 的直接跳过，
不浪费那两分钟。这个开关是 `auto_build_proxy`。

| | 原 AV1 | H.264 副本 |
|---|---|---|
| 单帧解码 | ~85 ms | ~28 ms |
| 单次 seek | **1.9 s**（最慢 3.3s） | **0.12 s** |
| 播放 | 慢放（约 12fps） | 接近实时 |

几点说明：

- **原始视频不动**，录制仍然读原件，只是"看"的时候用副本
- 副本与原件**同分辨率、同帧数、同时长**，所以小地图坐标和标注时间完全通用
  （这也是不缩小的原因：框选出来的圆心要能直接用在录制上）
- 转码是一次性的：459 秒的视频约 2 分钟，产物比原件大（AV1 压缩率更高）
- 副本不再需要时直接删掉那个 `.proxy.mp4` 即可；原件更新后旧副本会自动失效

因为没有音频就没法预览声音，副本会保留音轨（`-c:a copy`）。

### 播放倍速

工具条上的倍速下拉：`0.5x / 1x / 2x / 4x`，只影响预览，不影响录制与导出。

`MediaPlayer` 不支持变速，所以**非 1x 时自动静音**——与其让声音和画面对不上，
不如干脆不出声；切回 1x 会从当前位置继续出声。

## 目录结构：一个视频一个文件夹，一个文件夹一个 JSON

```
F:\GENSHIN1\video\
├── downloads\                 下载的原始视频（按标题命名）
│   └── 【官方 MV】..._P1.mp4
└── routes\
    ├── p5\                    ← 一个视频 = 一个文件夹
    │   ├── p5.json            ← 唯一的交付 JSON（导入 BetterGI 的就是它）
    │   ├── debug.csv          录制采样点（免重录重建用）
    │   └── project.json       编辑状态：滑翔窗口 + 点位操作
    ├── p3\
    │   ├── p3.json
    │   └── debug.csv
    └── _archive\              设置改过的旧版本，留档不参与编辑
        └── p5_OLD_resample3_rdp0.5.json
```

这样三件事自然成立：

- **一个视频一个 JSON**：JSON 就在同名文件夹里，不会出现第二个候选
- **不会串味**：载入 p3 的 CSV 不可能覆盖 p5 的 JSON（输出路径由文件夹决定）
- **下次打开继续编辑**：`project.json` 记着标了什么，`debug.csv` 记着采到的点

`routes` 根目录可以在配置里改（`RouteDir`），但每条记录的子目录由视频名自动派生，
界面上只读显示，不需要手填。改「路线名」等于切换整个工程目录。

旧版把 JSON 和调试 CSV 平铺在 `output\routes` 和 `output\debug` 下。
首次启动会自动迁移：已存在的 `p*.json` / `p*_debug.csv` 会被搬进对应文件夹，
其余变体挪到 `_archive`。

## 边看视频边标注

「视频与标定」页是一个内嵌播放器。标记的全部意义就是"我看到这一帧，在这里加东西"，
所以时间轴必须和要求对齐，而不是靠拖滑块猜。

画面用 OpenCV 逐帧解码显示，不是 MediaElement。原因是要**帧准确**：
标一个点必须落在你正看着的那一帧上，解码器能给出确切的帧号和时刻；
同时也避免了依赖系统解码器（不同机器装没装 HEVC 差别很大）。

### 拖框选小地图

小地图圆心与半径不用手填：在画面上拖一个框圈住小地图，松手就自动算好。

- 拖的时候有虚线框，还有一圈绿色预览，告诉你最终会框成什么样
- 松手后圆心 = 框中心，半径 = 框的宽度与高度的一半的均值（围着圆形画框时最贴近）
- 拖的过程中按 **Esc** 取消
- 算完会立刻重画画面并更新右侧裁剪图，配置也一并存盘

比手填三个数字省事，尤其是换了一个分辨率不同的视频时——原来的圆心会偏，重新框一次就正了。

拖动不会卡：定位是在后台线程解码的，拖动过程中只保留最新一次请求，
所以拖多远都只解码一次，界面也不会冻结。慢只是慢在解码本身
（AV1 见上一节），窗口始终是可操作的。

| 操作 | 按键 |
|---|---|
| 播放 / 暂停 | 空格 |
| 逐帧后退 / 前进 | ← / → |
| 后退 / 前进 1 秒 | Shift + ← / → |
| 标记滑翔（起点、终点各按一次） | **F8** |
| 在当前帧添加点位操作 | **F9** |
| 收起 / 展开左侧参数栏 | **Ctrl + B** |

按钮也都还在，但按键才是顺手的用法。

**为什么是 F8/F9 而不是字母**：中文输入法会吞掉字母键，`M`、`A` 根本到不了窗口
（空格和方向键能过）。这是实测踩出来的坑——一开始绑的是 M/A，按了没反应。
功能键不会被输入法拦截。

### 补标漏识别的滑翔

YOLO 漏检某段滑翔时，不用去改模型参数：

1. 空格播放，看风之翼什么时候展开 → 暂停，按 **F8**（起点记下）
2. 继续播放到落地前 → 暂停，再按 **F8**（窗口闭合）
3. 表格里出现一行「手工标记」，就是这段

两次按键间隔小于 0.3 秒会被拒绝并提示，避免误连点。

### 标注条：一眼看出哪些已经标了

时间轴上方有一条缩略标注条，把整段视频的标注压在一行里：

| 元素 | 含义 |
|---|---|
| 蓝色块 | 检测到的滑翔窗口 |
| 橙色块 | 手工补的滑翔窗口 |
| 绿色竖线 | 点位操作 |
| 红色竖线 | 当前播放位置（播放时实时移动） |
| 灰色 | 该行被取消勾选（不会写进 JSON） |

点击或拖动标注条直接跳转，悬停显示那一段的时间与类型。
右侧图例给出「滑翔 N 段 · 动作 M 个」的计数——**数字对不上就是还没标完**。

播放头落进某段滑翔或某个动作附近时，时间旁边会亮一个徽标，
例如「滑翔 18.5–27.5s」，用来确认看到的那一帧确实属于这段。

### 打开已有路线时自动回填

打开一个已经导出过的路线，会依次尝试：

1. 读 `project.json`（自己标过的，最准）
2. 读旧版 sidecar 并迁移
3. **直接读已导出的 JSON**：把 `debug.csv` 重跑一遍简化，用坐标把 JSON 的路径点和
   采样点对上，于是 `move_mode = fly` 的路径点能反推成滑翔窗口，
   `action` / `orientation` 能反推成点位操作

第 3 条是为了让**旧的路线也能被检查**：p5.json 里 7 个 fly 点被还原成 4 段滑翔窗口
（相邻的合并了），实测能对上 85/86 个坐标。

坐标对齐不上时不会瞎猜，会在日志里说明原因（点数是 86 还是 87 这种差异不影响，
因为它按坐标匹配而不是按序号）。

### 下次打开继续编辑

`project.json` 存标注，`debug.csv` 存在采到的点。打开时两者一起载入，
所以**不用重跑视频**就能直接「重新导出」，也能继续加标注。

| 文件 | 内容 |
|---|---|
| `<路线目录>\project.json` | 滑翔窗口 + 点位操作（含启停状态） |
| `<路线目录>\debug.csv` | 录制采样点 |

改动后 0.9 秒自动写盘，关窗口时再写一次。所以标完可以直接关，下次打开还在。

注意：**重跑一次检测会用新结果覆盖滑翔表格**（检测结果通常比手工更全）；
如果重扫后仍有漏检，再按 F8 补一次即可。

## 点位操作（绑定视频画面）

「点位操作」页用来在视频的某个时刻挂一个操作。绑定的是**时间**而不是路径点序号——
因为路径点会随简化参数变化，而时间不会；导出时才吸附到时间最近的路径点（容差 3 秒，
超出则报"未找到附近的路径点"而不是乱猜）。

一行可以同时设置四件事：

| 列 | 作用 |
|---|---|
| 动作 | 到达该点时执行什么（见下表） |
| 点位类型 | 例如 `orientation` 方位点，让角色转向该点做定位校准 |
| 移动模式 | 单点改成 jump / climb / dash 等，例如这里需要跳一下 |
| ΔX / ΔY | 把这个点的坐标整体挪一点（游戏单位），修匹配偏差 |

操作方式：

1. 到「视频与标定」页播放到需要的画面
2. 按 **F9**（或点「在此帧添加点位操作」）
3. 在下拉框里选动作、类型，必要时填 ΔX / ΔY
4. 点「重新导出」——不读视频，毫秒级写进 JSON

**双击一行**会跳到对应的画面，方便确认标得对不对。
**双击滑翔窗口的一行**同样会跳到该段起点。

### 动作列表是 BGI 的固定枚举，没有"任意按键"

这一点必须说清楚：BetterGI 的地图追踪没有"按某个键"这种自由 action，
它只认 `Handler/ActionFactory.cs` 里注册的那些。键盘只能通过这些内置动作间接触发：

| 动作 | 实际按下的键 / 行为 |
|---|---|
| `use_gadget` 使用小道具 | 按小道具键（Z） |
| `stop_flying` 下落攻击 | 跳跃 + 普攻 |
| `normal_attack` / `elemental_skill` | 普攻 / 元素战技 |
| `fight` | 触发自动战斗 |
| `pick_around` / `pick_up_collect` / `nahida_collect` | 拾取类 |
| `set_time` | 设置游戏时间，参数 `H:M` |
| `force_tp` | 在该点触发传送 |
| …其余见下拉框 | |

写一个不在列表里的 action，BGI 会直接抛「未知的后置 action 类型」。
所以下拉框只给真实存在的那些，参数提示也写在 tooltip 里
（例如 `use_gadget` 的参数是最大等待秒数，`set_time` 是 `H:M`）。

## 导出：正式产物 vs 另存一份

| 按钮 | 写到哪里 | 用途 |
|---|---|---|
| 重新导出 | `routes\<视频名>\<视频名>.json`（工程的正式产物） | 反复微调后刷新同一个文件 |
| **导出到…** | 你选的目录，文件名取路线名 | 交给 BetterGI 用，通常指向它的 `AutoPathing` 目录 |

「导出到…」的几个细节：

- 目录选择器默认打开左侧参数栏里的「导出目录」，用一次就记住
- 导出前会**按当前界面状态重建路径点**，所以即使没先点「重新导出」，副本也和屏幕上的滑翔窗口/点位操作一致
- 目标已存在会先问一句，不会静默覆盖
- **不会改变工程的正式路径**——副本只是副本，之后点「重新导出」仍然写回 `routes\`

「导出目录」留空时，选择器从当前路线的目录开始。

## 架构

原来录制流程写在控制台的菜单函数里，UI 只能靠模拟按键去驱动。现在抽成共享的
`RecordingPipeline`，窗口和控制台走**同一份实现**：

```
RecordingPipeline            （VideoPathTool/RecordingPipeline.cs）
  ├─ GetMatcher()            地图层 + SIFT，按目录缓存
  ├─ Record()                遍历视频，产出位置点（支持暂停/热改/进度回调）
  ├─ ScanGlides()            YOLO 优先，缺失时回退小地图启发式
  ├─ BuildWaypoints()        简化 + 标注 fly + 应用点位操作
  ├─ SaveJson() / SaveCsv()  导出（含 action / action_params）
  └─ LoadFromCsv()           从调试 CSV 恢复

Core 里的配套
  ├─ VideoDownloader         yt-dlp 封装（进度、已存在、取消）
  ├─ AppPaths                三个固定目录 + 路径推导
  ├─ PointAction / ActionCatalog / PointActionStore
  │                          点位操作模型、BGI 动作表、sidecar 持久化
  └─ PauseToken / RunProgress 暂停闸门、进度类型

RecordingScheduler           （UI 侧，包装成后台任务）
  ├─ Start / Pause / Resume / Stop
  ├─ RescanGlidesOnly        不重录位置，只重扫滑翔
  └─ SetResult               注入外部结果（CSV 载入）

MainWindow                   （纯展示 + 参数绑定）
```

控制台的 `Record()` 也改成调用这条流水线，两边不会走偏。控制台行为不变，
已用 15 秒片段做过回归。另外控制台还有两个自检命令：

```
VideoPathTool glide-test  <model.onnx> <video> [fps] [conf]
VideoPathTool download-test <url> [dir]
```

## 遇到的两个坑

**WPF 不能开 `InvariantGlobalization`**
UI 项目一开始继承了控制台的 `<InvariantGlobalization>true</InvariantGlobalization>`，
结果一打开「滑翔窗口」就抛
`Cannot find non-neutral culture related to 'en-US'` —— WPF 的绑定引擎给
DataGrid 里的 double 找文化信息时崩了。已从 UI 项目移除，并在 csproj 里写了注释。

**复选框要双击**
`DataGridCheckBoxColumn` 需要先点进编辑模式再点一次才能切换。表格改成模板列，
里面直接放 CheckBox，单击即可勾选——审阅十几段滑翔时这点差别很明显。

**滑块只能点刻度**
Slider 默认 `IsMoveToPointEnabled=false`，点轨道空白处不动。标定页需要随便跳帧，
已开启该属性。

## 还没做的

- 没有轨迹预览图（把路径画在地图上）——目前只能看 JSON 和断点列表确认几何
- 标注条不能拖动缩放时间范围（长视频里滑翔段会挤成几像素）
- 从 JSON 反推滑翔时，密度取决于路径点：一段短滑翔可能一个路径点都没有，就还原不出来
- 没有撤销/重做
- 播放器没有倍速播放，也还没有"只播这一段"
- 滑翔窗口的表格不能按置信度排序过滤（数据量小，暂时用不上）
- 关闭窗口会中断正在运行的任务（没有"确认后退出"）
- 下载不支持需要登录 / 大会员的站点（没有接 cookies）
- 只下链接指向的单个视频，不会把整个合集批量拉下来（合集里每P要单独给链接）
- BGI 的 `stop_flying` / `up_down_grab_leaf` 是"前置动作"，和其他动作混在一个下拉框里，
  没有区分标注
