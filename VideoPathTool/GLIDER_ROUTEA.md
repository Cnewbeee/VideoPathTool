# 路线 A 实测报告：小地图风之翼检测

对 `p5.mp4`（1920×1080, 30fps, 396s）的完整实测。实现落在
`VideoPathTool/Core/GlideDetector.cs`，实验脚本见 `video/scripts/`。

## 结论

**可做到"候选"级别（精确率 0.64，F1 0.75），做不到可靠自动化。**
真滑翔段基本都能抓到，但会混入误报，必须人工核对后再用。

---

## 1. 先排除的方案（都有实测数据）

| 方案 | 实测结果 |
|---|---|
| 风之翼像素模板匹配 | 只有模板自身那帧得 1.00；**同一个连续滑翔**的相邻帧只有 0.10~0.45（翼膜在扇动/扭转） |
| 边缘模板匹配 | 同上，仅自身帧 0.98 |
| 对称性 / 亮度 / 饱和度 | **传送门特效**得分最高（sym=0.92），真值进不了 top |
| 霍夫水平长线 | 走路帧 8 条 vs 滑翔帧 1~9 条，无区分度 |
| 剪影形状（最佳组合） | F1=0.351，**精确率仅 0.248** |
| 官方 `Space` 键模板 | 剪辑视频里提示被裁掉：3960 帧仅 16 帧 >0.5，全是孤立单帧，分布单峰无法切分 |
| 箭头朝向（PCA 主轴） | t=17~34s 之间反复 180° 跳变（-122° ↔ +53°），不可靠 |
| 速度 + 转向（运动学） | 85~90s 滑翔 5.98 u/s，而 32~37s 走路 10.20 u/s —— **走路比滑翔还快** |
| 小地图玩家图标（严格阈值） | 风之翼展开前后 area 246.8→244.0、l/w 3.73→3.78，**完全不变** |

BGI 判定飞行靠的是**屏幕右下角的「Space」跳跃提示图标**
（`BvStatus.cs:225` → `SpaceKey`/`XKey` 模板，ROI `keyTip`），不是看风之翼。
这个逻辑在实时游戏里成立，但 p5 是剪辑过的视频，提示被裁掉了。

## 2. 可行信号：小地图上的风之翼标记

### 观察

小地图上**画的不是角色小图标，而是风之翼的形状**。展开风之翼时，
小地图上出现一个**长而细的青色翼形标记**；平时是一个粗短的箭头。

![小地图对比](F:/GENSHIN1/video/output/analysis/minimap_compare.png)

对比图里能清楚看到：6 张真滑翔（GLIDE）的小地图都有那个长条翼形标记，
4 张误报（FALSE）标记的是**飞行轨迹线**（更细更长）。

### 判据

```
wing = (标记长宽比 >= 6.5) AND (标记质心移动量 >= 0.1 px/样本)
```

**长宽比**用 PCA 主轴算，对旋转缩放不变（风之翼在扇动、角色在转身，
朝向每帧都在变，绝对坐标或朝向都不稳）。

**质心移动量**用来排除**世界地图界面**：世界地图是静态 UI，
上面的青色标记完全不动（实测 0.000），而实时小地图上的标记会随角色移动。

```
t=27.0  l/w= 7.81  质心移动=0.857   <- 真滑翔
t=49.0  l/w=16.35  质心移动=1.038   <- 真滑翔
t=324.0 l/w= 6.88  质心移动=0.000   <- 世界地图（误报）
t=327.0 l/w=26.63  质心移动=0.000   <- 世界地图（误报）
```

### 采样率是决定性因素

风之翼在扇动，标记的形状每帧都变。用录制用的 2 FPS 采样，
经常错过伸长的姿态：

| 采样率 | F1 |
|---|---|
| 10 FPS | **0.75~0.99** |
| 2 FPS | 0.32 |

所以实现里**单独跑一遍 10 FPS 的标记采样**（不做模板匹配，很便宜）。

## 3. 实测性能

人工标注的真值（肉眼逐帧核对 contact sheet 与候选帧）：
t=15.0~31.0s、t=44.0~53.5s、t=110.0~119.0s 三段滑翔。

| 版本 | F1 | 精确率 | 召回率 |
|---|---|---|---|
| l/w 单独 | 0.88~0.96 | — | — |
| l/w + 质心移动 | **0.75** | **0.64** | 0.92 |
| 随机基线 | 0.15 | — | — |

（早期测得的 F1=0.994 是在**同一份数据上调阈值**得到的，属于过拟合；
做了训练/测试分离后，真实值是 0.75。）

最终配置下的检测结果：

```
  14.90..  32.70   <== 真滑翔
  35.40..  53.70   <== 真滑翔
 111.90.. 114.80   <== 真滑翔
 115.90.. 119.40   <== 真滑翔
 137.30.. 140.30   误报
 375.40.. 379.20   误报
```

## 4. 试过但没用的排除手段

| 尝试 | 结果 |
|---|---|
| 限制标记面积 ≤1500 px（排除轨迹线） | **更差**：F1 从 0.70 掉到 0.22。"取最大连通域"本身在多数帧选中的就是轨迹线，面积上限会把真样本一起砍掉 |
| 选"最实心"的连通域 | 不稳定：小碎块会导致指标跳变 |
| 只选面积 60~400 的连通域 | 分离度 0.89 但 F1=0.268 |
| 用轨迹线长度/斜率 | 分离度 0.83 / 0.05，斜率完全无区分度 |
| 风之翼字形模板匹配（24 个旋转角） | F1=0.201（模板抓到的其实是轨迹线） |
| 训练/测试分离验证 | 证伪了 F1=0.994 的乐观数字 |

## 5. 已知局限

1. **精确率 0.64** —— 每 3 段报警约 1 段是误报。误报多来自小地图上的青色
   飞行轨迹线。
2. **窗口边界偏宽** —— 报告的窗口会略微包含起跳前与落地后的站立时间。
3. **依赖小地图** —— 没有可用小地图的路线无法分析。

**因此 `detect_glide` 默认关闭。导出后请人工核对 `move_mode: "fly"` 的路径点。**

## 6. 使用方法

```
[45] 滑翔检测: True/False        # 默认 False
[46] 滑翔标记最小长宽比: 6.5
[47] 滑翔标记最小移动量: 0.1
[48] 滑翔段合并间隔(秒): 1.0
[49] 滑翔最短时长(秒): 2.0
[50] 滑翔标记采样率(FPS): 10
```

录制或「从调试CSV重建」后，控制台输出：

```
滑翔候选: 6 段，标记为 fly 的路径点 15 个
  14.9s ->  32.7s  置信度 7.35  minimap wing marker (high aspect ratio + moving marker)
  ...
  提示: 判定依据是小地图上的风之翼标记（长宽比高 + 标记在移动），
        窗口边界会略微包含起跳前与落地后的站立时间，请人工核对后再用于实战。
```

导出的 JSON 里对应路径点带 `"move_mode": "fly"`。BGI 侧 `PathExecutor.MoveTo`
会按空格起跳并保持飞行（`MoveModeEnum.Fly`）。

「从调试CSV重建」会读取同目录下的 `*_debug_markers.csv`（标记采样结果），
所以标记采样只需要做一次。

## 8. 仍推荐的替代方案

| 方案 | 状态 |
|---|---|
| **让博主补录保留 UI 的素材** | 官方 `Space` 模板直接可用，精度 100% —— 最推荐 |
| **人工标注 3~5 段滑翔** | 成本极低，绝对可靠 —— 最推荐 |
| 本方案（小地图风之翼标记） | F1=0.75，精确率 0.64 —— 自动化首选，但需人工核对 |
| 画面找风之翼 | 最佳 F1=0.351，精确率 0.248 —— 不可行 |
| 运动学（速度+转向） | F1≈随机基线 —— 不可行 |
